GradeChecker.java

A staircase of checks

Questions run top to bottom and stop at the first yes. Drag the marks and count how many checks actually happen.

The syntax

if (condition1) {
    // runs when condition1 is true
} else if (condition2) {
    // runs when condition1 is false and condition2 is true
} else {
    // runs when none of the conditions is true
}
condition1
Checked first. If it is true its block runs and the rest of the chain is skipped.
condition2
Checked only when everything above it was false. Add as many else if steps as you need.
else
Optional fallback with no condition. It runs when every check above failed.

The shape of it

grade: C checks run: 3 of 3

The code

int marks = 72;if (marks >= 90) {    System.out.println("Grade A");} else if (marks >= 75) {    System.out.println("Grade B");} else if (marks >= 60) {    System.out.println("Grade C");} else {    System.out.println("Needs improvement");}

Struck-through lines were never reached. Faded lines were checked and came back false.

Output

What to point out

  • The chain stops at the first true test. Everything below it is never even looked at.
  • That is why each test only needs a lower bound. marks >= 75 already implies and below 90, because 90 and above was handled on the line before.
  • Order matters enormously. Put >= 60 first and every passing student gets a C.
  • The final else needs no condition — it catches whatever is left.

Try this with the class

  • Set marks to 95 and ask why it does not also print B and C.
  • Watch the checks counter: 95 costs one check, 30 costs three. Why?
  • Ask what happens at exactly 75 and exactly 74.
  • Ask them to predict the grade before you release the slider.
