Two gates

One file, two independent conditions. Take them one at a time: && wants every input true, || is happy with one.

What to point out

  • && is true only when both sides are true. || is true when at least one is.
  • Java short-circuits. With &&, a false left side settles it and the right side is never evaluated. With ||, a true left side does the same. The unread operand goes dashed in the diagram and struck through in the code.
  • That is not just a speed trick. It is what makes if (s != null && s.length() > 0) safe.
  • Both conditions live in the same main method. They run one after the other and have nothing to do with each other.

Try this with the class

  • Drop age below 18 and watch hasLicense get struck out. Ask why Java stopped reading.
  • Keep age under 18 and flip the licence back and forth. Ask why the output does not change.
  • Find the one dice value where the || is true but the number is odd. (It is 1.)
  • Ask what & and | do differently from && and ||.
