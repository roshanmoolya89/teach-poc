The pieces

Source code
The .java file you type. Plain text, readable by people, meaningless to a CPU.
javac
The compiler. Checks the source for mistakes and translates it. Runs once, before the program does.
Bytecode
The .class file javac writes. Instructions for the JVM rather than for any real processor, so the same file runs everywhere.
JVM
Java Virtual Machine. Loads the bytecode, checks it, and turns it into machine code as the program runs.
JRE
Java Runtime Environment. The JVM plus the ready-made classes every program leans on, such as String and System.
JDK
Java Development Kit. The JRE plus the tools for writing programs: javac, javap, jar.
OS / Hardware
What finally does the work. The JVM is built separately for each one, which is why your bytecode does not have to be.

What to point out

  • Three nested boxes: the JDK contains the JRE, which contains the JVM. Since Java 11 there is no separate JRE to download, so installing the JDK gives you all three.
  • Two commands, two moments. javac is compile time and happens once. java is run time and happens every time.
  • Bytecode is the same on every machine. The JVM is the part that differs per operating system. That is “write once, run anywhere”.
  • The arrow going up into javac: the compiler is itself a Java program, so it runs on the JVM too.
  • A missing semicolon is caught by javac and the program never starts. Dividing by zero is caught by the JVM, while it runs.

Try this with the class

  • Run javac Hello.java, then list the folder. Ask what the new file is, and open it in an editor to see that it is not text.
  • Run javap -c Hello and match the four instructions to the one line of Java.
  • Delete Hello.java and run java Hello. It still works. Ask why.
  • Now delete Hello.class instead and run java Hello. Read the error together.
